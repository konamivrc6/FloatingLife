# Markdown 排版触发器

在 Markdown 里敲 `///fmt` 再按回车，即用 [_tool_fmt_md.py](../../_tool_fmt_md.py) 排版当前文件。

## 用法

1. 光标停在要排版的位置，敲 `///fmt`，按回车。

2. 扩展删掉 `///fmt` 和这次回车，保存文件，以当前文件路径调用排版脚本。

3. 脚本跑完后把结果换回编辑器，Ctrl+Z 可以整步撤回。

触发词只认「紧接着回车」这一种。敲完 `///fmt` 直接点鼠标走开不会触发，那段文字会留在正文里。fenced 代码块里的 `///fmt` 同样不触发——那里多半是正文或示例。

命令面板里的 `Markdown: 排版当前 Markdown 文件` 等价于不带触发词的调用，适合绑定快捷键，或在没敲触发词时补一次。

## 设置

| 键 | 默认值 | 说明 |
|---|---|---|
| `markdownFmt.enabled` | `true` | 是否响应触发词。命令面板命令不受影响 |
| `markdownFmt.trigger` | `///fmt` | 触发词 |
| `markdownFmt.scriptPath` | `_tool_fmt_md.py` | 相对路径按工作区根目录解析，没开工作区时从文件所在目录逐级向上找；也可填绝对路径 |
| `markdownFmt.pythonPath` | `python` | `python3` 是应用商店占位程序，别改 |

## 实现要点

**​触发发生在回车时，不在最后一个字符时。​** VS Code 的 `onDidChangeTextDocument` 是逐键上报的：敲 `///fmt` 会发六个事件，每次 `change.text` 只有一个字符，拿它跟整串比永远不成立。改在回车时判断，只需看 `contentChanges` 里那次换行插入，再从插入点往前截 `len(trigger)` 个字符比对即可。

**​删除范围包含这次回车。​** 光标停在段尾时敲 `///fmt` 再回车，文档里会多出 `\n`。若只删触发词，多出来的换行会和原有的空行凑成 `\n\n\n`，而排版脚本把三连空行当成场景分隔。所以删除范围必须覆盖整次插入。

**​只认「一次插入就是回车」的改动。​** `ENTER_INSERT` 限定了换行 + 可选自动缩进 / 列表符号 / 引用号。这样既能识别列表里回车自动补出的 `- `，又能避免把「粘贴一段以 `///fmt` 结尾的多行文本」误当成命令——那种改动换行后面带着正文，不匹配。

**​先保存再跑。​** 脚本读写的是磁盘，缓冲里没保存的字它看不见。

**​跑完主动读盘回填。​** 不能只指望文件监视器：脚本写盘后，VS Code 可能已经自动 reload（内容自然一致），也可能还没轮到。所以进程退出后读一次磁盘，和缓冲区比对，不同就整体替换。替换前检查 `doc.isDirty`——如果排版那零点几秒里又敲了字，覆盖会吞掉新输入，此时只提示、不动。

**​中文输出要强制 UTF-8。​** 管道重定向时 Python 的 stdout 走 locale 编码（本机 cp936），Node 按 utf8 解会得到乱码。spawn 时带 `PYTHONUTF8=1` + `PYTHONIOENCODING=utf-8`，对脚本读写文件无影响（它自己显式写了 `encoding='utf-8'`）。

**​路径用参数数组传，不走 shell。​** 文件名里有空格和 `·`，走 shell 就得处理引号转义，出错面大得多。

## 已知边界

- 触发词和回车是一起删的，撤销栈里也是两步（删触发词、回填结果）；连续两次 Ctrl+Z 才回到敲触发词之前。

- 回填后光标按字符偏移近似还原。首次排版全篇时空白增删较多，落点可能偏。

- 脚本跑完会写 `X_Original.md` 备份（无改动时不写），格式与在终端里直接调用一致。

- 同一文件不允许并发排版，第二次触发会被忽略。

- 超时 60 秒，超时即杀进程。
